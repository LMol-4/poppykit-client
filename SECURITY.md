# Security reporting

Do not put credentials, tokens, private keys, personal records or exploit details
in a public issue. Use this repository's GitHub **Security → Report a vulnerability**
when private reporting is enabled. If it is unavailable, request a private contact
from the repository owner without disclosing the vulnerability publicly. The owner
must enable/confirm that route; no response SLA is promised.

Include affected commit/version, a minimal reproduction using synthetic data,
impact and the trust boundary involved. These draft packages have no promised
support window or response SLA. Custom vaults, issuers, browser controllers,
proxy routing and deployment policy remain operator responsibilities. Redaction
and scoped authority do not isolate an unrestricted same-user program.
